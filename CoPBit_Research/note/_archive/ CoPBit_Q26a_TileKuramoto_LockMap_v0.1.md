⸻

1. 목적

PPU에서 여러 개의 CoPBit 타일(각 타일은 1024 lanes)을 Kuramoto coupling으로 묶었을 때,
	•	결합 강도 K
	•	타일 간 주파수 드리프트 표준편차 drift_std_deg
	•	타일별 위상 노이즈 표준편차 theta_std_deg
	•	타일 개수 n_tiles (64 → 256)

에 따라 전체 타일들이 글로벌 위상 기준으로 잘 lock 되는지 / 실패하는지를 맵으로 정리하는 것이 목표.

이를 통해:
	1.	PPU 전체가 하나의 “큰 위상 클럭”처럼 동작 가능한지,
	2.	메모리/버스 쪽에서 이미 확인된 θ_std ≤ 1° 안정 영역과 연동되는지,
	3.	실제 칩 설계에서 필요한 K · drift · θ_std 스펙 범위를 감각적으로 잡는 것이 목적이다.

⸻

2. 실험 설정 요약

2.1. 공통 설정
	•	타일 개수
	•	1차: n_tiles = 64 (초기 확인용)
	•	2차: n_tiles = 256 (확장 안정성 확인, 본 정리 메인)
	•	Kuramoto 결합 강도 K
	•	K ∈ {0.0, 0.05, 0.1, 0.2, 0.3}
	•	타일 간 드리프트 표준편차 (deg)
	•	drift_std_deg ∈ {0.01, 0.05, 0.1}
	•	타일별 위상 노이즈 표준편차 (deg)
	•	theta_std_deg ∈ {0.1, 0.3, 0.5}

각 타일은 내부적으로 이미 PhaseLock_std(p_ref 기반) 구조로 안정화된 상태라고 가정하고,
여기서는 “타일의 중심 위상”들만 Kuramoto 네트워크로 묶어서 글로벌 락을 보는 구조이다.

3. 평가 지표 정의 (CSV 컬럼)

각 (K, drift_std_deg, theta_std_deg, n_tiles) 조합에 대해 시뮬레이션 후 다음 값 기록:
	•	steady_sigma_deg
	•	충분히 긴 스텝 이후, 타일 위상 분포의 표준편차 (deg)
	•	≈ 0.1° ~ 1° 수준이면 매우 잘 lock 된 상태
	•	≈ 100° 근처면 완전 랜덤 (lock 실패)
	•	lock_step
	•	글로벌 위상 분산이 설정한 임계치 이하로 처음 내려가는 시점의 스텝 번호
	•	-1이면 끝까지 lock 실패
	•	lock_frac
	•	전체 시뮬레이션 동안 lock 상태로 유지된 비율 (0.0~1.0)
	•	≈ 1.0 : 초반에 lock → 끝까지 유지
	•	≈ 0.3~0.7 : 중간 이후 lock되거나, 일시적 lock
	•	-1.0 : lock 실패
	•	lock_success
	•	1 : 최종적으로 글로벌 락 성공
	•	0 : 최종적으로 락 실패

⸻

4. 64-Tile vs 256-Tile 전반 경향
	•	64 tiles 결과 (Q26a 기본)
	•	이미 K ≥ 0.1, drift_std ≤ 0.1°, theta_std ≤ 0.5° 영역에서
대부분 안정적인 글로벌 위상 락을 보여줌.
	•	“PPU 여러 타일을 Kuramoto로 묶을 수 있다”는 1차 확인 단계.
	•	256 tiles 결과 (Q26a_ppu_tile_kura_lock_map_256tiles.csv)
	•	타일 개수를 4배로 늘렸음에도,
	•	적절한 K를 선택하면 오히려 더 매끈한 lock 패턴을 보임.
	•	전반적 결론:
	•	타일 수를 늘려도 Kuramoto 네트워크가 더 무너지는 것이 아니라,
**제대로된 K·drift·θ_std 영역에서 더 강하게 자기 평균화(self-averaging)**가 일어남.
이로써, **“타일이 많아질수록 Kuramoto 기반 글로벌 위상은 오히려 더 안정”**이라는 감각을 확인했다.

5. K 값별 상세 요약 (256 tiles 기준)

5.1. K = 0.0 (no coupling)
	•	모든 조합에서:
	•	steady_sigma_deg ≈ 100°
	•	lock_step = -1, lock_frac = -1.0, lock_success = 0
	•	해석:
	•	타일 간 결합이 전혀 없으면, 각 타일이 제 위상대로 떠다녀서
PPU 전체 레벨의 글로벌 기준 위상은 절대 형성되지 않는다.
	•	즉, PPU를 하나의 거대한 위상 클럭으로 쓰려면
Kuramoto 또는 그에 준하는 글로벌 coupling은 필수라는 것을 수치로 확인.

⸻

5.2. K = 0.05 (약 결합)
	•	성공하는 조합 (lock_success = 1) 예:
	•	drift_std = 0.01, theta_std = 0.1
	•	drift_std = 0.01, theta_std = 0.3
	•	drift_std = 0.05, theta_std = 0.1 등
	•	특징:
	•	steady_sigma_deg ≈ 0.3° ~ 1.0° 수준까지 떨어지는 케이스는 있으나,
	•	lock_step이 매우 늦게 나오거나 (예: 시뮬레이션 거의 끝),
	•	일부 조합은 아예 lock 실패.
	•	theta_std = 0.5 또는 drift_std = 0.1 수준으로 올라가면 대부분 실패.
	•	정리:
	•	K=0.05에서는 매우 이상적인 초미세 드리프트/노이즈에서만 겨우 lock.
	•	양산 설계 기준으로는 여유가 거의 없는 위험한 영역 → 피하는 것이 좋음.

⸻

5.3. K = 0.1 (중간 결합)
	•	성공 조합 (대표):
	•	drift_std = 0.01, theta_std = 0.1 / 0.3
	•	drift_std = 0.05, theta_std = 0.1 / 0.3
	•	drift_std = 0.1, theta_std = 0.1
	•	특징:
	•	steady_sigma_deg ≈ 0.25° ~ 0.9°
	•	대부분 lock_step ≈ 100 ~ 200 수준 → 초기 비교적 빠르게 lock
	•	다만
	•	drift_std = 0.1, theta_std = 0.1처럼 극단 경계에서는
	•	lock_step이 수만 스텝 이후에 나오고,
	•	lock_frac도 0.4~0.5 수준 (시뮬 중간 이후에 겨우 lock)
	•	실패 영역:
	•	theta_std = 0.5 조합은 거의 다 실패
	•	drift_std = 0.1, theta_std ≥ 0.3도 실패
	•	정리:
	•	연구/프로토타입 용으로는 의미 있는 영역.
	•	그러나 노이즈/드리프트 여유를 크게 보고 싶다면,
양산 스펙에서는 한 단계 더 강한 K 쪽(K≥0.2)을 쓰는 것이 안전.

⸻

5.4. K = 0.2 (강 결합 1)
	•	모든 조합 drift_std ∈ {0.01, 0.05, 0.1}, theta_std ∈ {0.1, 0.3, 0.5} 에서:
	•	lock_success = 1 (글로벌 락 100% 성공)
	•	특징:
	•	steady_sigma_deg:
	•	작은 드리프트/노이즈: ≈ 0.15° ~ 0.4°
	•	큰 드리프트/노이즈: ≈ 0.5° ~ 1.0°
	•	lock_step:
	•	대부분 수십~수백 스텝 이내에 lock
	•	lock_frac:
	•	0.8~1.0 근처 → 시뮬레이션 대부분 구간을 lock 상태로 유지
	•	정리:
	•	현실적인 드리프트/노이즈 조건에서,
	•	타일 256개까지도 매우 안정적으로 한 몸처럼 움직이는 K 영역.
	•	θ_std ≤ 1° 설계 타겟과 잘 맞고,
메모리/버스 쪽 PhaseLock_std 조건과도 자연스럽게 이어진다.

5.5. K = 0.3 (강 결합 2)
	•	K=0.2와 유사하게 전 영역 lock 성공.
	•	steady_sigma_deg는 대체로 K=0.2 대비 조금 더 타이트한 편.
	•	하지만:
	•	K가 너무 크면 실 설계에서 전류/전력/루프 안정성 측면에서 부담이 될 수 있으므로
	•	실제 칩에서는 K=0.2 전후를 기본 타겟으로 잡고,
	•	필요한 경우 국부적으로만 K를 더 키우는 방향이 현실적이다.

⸻

6. 종합 결론
	1.	Kuramoto coupling은 PPU 타일 전체를 하나의 위상 클럭으로 묶는 데 필수
	•	K=0인 경우, 타일이 64개든 256개든 글로벌 lock은 절대 형성되지 않음.
	2.	θ_std ≤ 1° + 적절한 K(K ≥ 0.2) 조합에서,
타일 수가 많아도 오히려 더 self-averaging이 일어나며 안정화
	•	64 tiles → 256 tiles로 확장해도 글로벌 락은 유지/강화.
	•	메모리/버스 쪽에서 이미 얻었던
	•	**“PhaseLock_std + θ_std ≤ 1°면 문제 없다”**는 결과와 자연스럽게 연결됨.
	3.	실 설계 스윗 스팟 (개략)
	•	타일 당 PhaseLock_std: θ_std_tile ≤ 1° 수준 확보
	•	타일 간 Kuramoto coupling:
	•	K ≈ 0.2 주변을 기본 타겟
	•	드리프트: drift_std ≤ 0.1° 설계 목표
	•	이 조건이면:
	•	PPU 전체가 거대한 3D 위상 기반 연산 네트워크로 동작 가능
	•	메모리/버스 모드와 PPU 모드를 같은 위상 인프라에서 공유하는 일관된 아키텍처가 성립.
	4.	타일 개수 확장 관점
	•	64 → 256 tiles에서 이미 안정성 확인.
	•	같은 Kuramoto 구조를 유지한다면,
	•	1024 tiles (즉, 1024×1024 lanes = 약 1M lanes) 까지도
	•	이론적으로는 동일한 메커니즘으로 확장 가능.
	•	실 구현에서는 K, 배선, 전력, 지연 등의 물리적 제약을 고려해야 하지만,
**“위상 동기화 관점에서의 기본 원리/알고리즘은 충분히 스케일링 가능”**하다는 것이 Q26a의 핵심 결과.

7. Q26a의 의미 (요약 한 줄)

Q26a 결과:
CoPBit PPU는 “타일 내부 PhaseLock_std + 타일 간 Kuramoto(K≈0.2)” 조합으로,
θ_std ≤ 1° 영역에서 64~256 타일 규모에서도 안정적인 글로벌 3D-위상 클럭을 형성할 수 있다.
